# Editing Guide — tanushhlath.com

The one document for maintaining this site. Everything a normal update
needs — text, events, photos, videos, skills, the Easter egg, colours,
SEO, deploying — is here, with the exact file and field.

**The golden rule:** content lives in `src/content/`, media lives in
`public/media/`. You edit data, not layout code. React components
(`src/components/`, `src/pages/`) only decide how things look; you should
almost never need to open them for a content change.

## 1. Quick start

```bash
npm install        # once, after cloning
npm run dev        # local site with live reload → http://localhost:3000
npm run build      # production build + checks; updates the live files at the project root
npm run start      # serve the finished build exactly like the host would → http://localhost:3000
```

A normal update is:

1. Put any new photos in their folder under `public/media/…` (§8).
2. Edit or add the record in `src/content/…`.
3. `npm run build` — it validates your content, rebuilds every page and
   fails with a readable message if something is wrong (a typo in an id, a
   link to a record that doesn't exist, a photo that isn't there).
4. Commit and push (§21). The site updates.

All the content files are TypeScript. You don't need to know TypeScript:
copy an existing record, keep the same shape, change the values. Your
editor underlines mistakes in red, and `npm run build` refuses to publish
a broken record.

## 3. Site identity

File: **`src/content/site.ts`**, object `site`.

| What you want to change | Field |
|---|---|
| Full name | `name` |
| Name in the top-left corner | `shortName` (shown in capitals) |
| Homepage statement (tagline) | `tagline` |
| Small label above the name on the homepage ("A person, not a résumé") | `heroKicker` |
| Short bio (homepage "Who I am", search descriptions) | `bioShort` |
| Long bio on the Me page (one string per paragraph) | `bioLong` |
| School | `school` |
| Location — one line (homepage, menu, footer) | `location.short` |
| Location — full sentence (Me page) | `location.long` |
| Where you live / where you study (used in structured data) | `location.home`, `location.school` |
| Email | `email` **and** the `mailto:` entry in `social` |
| LinkedIn (and any other profile) | `social` → `{ label, url }` |
| Portrait | `photo.src` (large), `photo.small` (640 px), `photo.alt` |
| Footer sentence under the name | `footerLine` |
| The tiny Easter-egg joke in the footer | `easterEggHint` |

The website address (`https://tanushhlath.com`) is `SITE_URL` in
`src/routing/paths.ts` — change it only if the domain changes.

## 5. Page headings, menu names and descriptions

**Menu** — `src/content/site.ts`, object `navigation`:
`home`, `primary` (numbered 01–04 in the order listed), `secondary`
(Archive, Explore). Each item: `{ href, label, description }`.

**Page titles, search descriptions and headings** — `src/content/pages.ts`,
object `pages`, one entry per page (`home`, `story`, `work`, `me`,
`beyond`, `archive`, `explore`, `notFound`):

- `title` — short page name. The browser tab shows "title — Tanushh Lath".
- `description` — the Google / link-preview snippet. Keep it under 160 characters.
- `kicker`, `heading`, `intro` — the words at the top of the page.
- `sections` — optional extra sections built from blocks (§13).

**Labels inside pages** (tab names, button text, empty states) are in the
other objects in the same file: `storyCopy`, `workLenses`, `workCopy`,
`detailCopy`, `meCopy`, `beyondModes`, `beyondCopy`, `exploreLenses`,
`exploreCopy`, `archiveCopy`, `notFoundCopy`.

## 6. Projects (Work → Built)

File: **`src/content/projects.ts`**, array `projects`.

### Add a project
Copy an existing record, paste it at the top of the array, and change:

```ts
{
  id: "my-new-project",          // lowercase-with-dashes; becomes /work/my-new-project/
  title: "My New Project",
  year: 2026,
  dateLabel: "2026 — ongoing",   // optional; shown instead of the year
  category: "ai",                // ai | social-impact | web | research | product
  status: "in-progress",         // concept | in-progress | shipped | completed | paused | archived
  importance: "significant",     // featured | significant | archive (§7 explains)
  summary: "One line that says what it is.",
  problem: "…", motivation: "…", concept: "…", role: "…",
  process: ["Step one", "Step two"],
  challenges: "…", outcome: "…", impact: "…", lessons: "…",
  tools: ["Tool A", "Tool B"],
  links: [{ label: "Try it", url: "https://…" }],   // external links get ↗ automatically
  relatedSkills: ["product-thinking"],
  relatedEvents: ["masters-union-ai-hackathon"],
  relatedStory: ["building-with-ai"],
},
```

Every field after `summary` is optional — leave out what you don't have.
Photos: create `public/media/projects/my-new-project/` and add images
(§8); they appear automatically, and until then the card uses a designed
typographic visual.

### Edit a project
Change the fields in place. Don't change `id` unless you must (it's the
URL); if you do, add the old id to `aliases: ["old-id"]` so the old
address redirects.

### Remove a project
Delete its record. Then run `npm run build` — if anything still points to
it (a skill, a story moment, `home.featuredWork.ids`), the build tells you
exactly which file and field to fix. Delete its media folder too.

## 7. Events and recognitions

Events are everything under **Work → Did**. A recognition (a medal, a
place, a final round) is stored **on the event it belongs to** — the
**Recognized** lens, the Archive, Explore and the skill evidence are all
generated from these records, so nothing is ever written twice.

Files: **`src/content/events/<category>.ts`** — one file per Did category:

| File | Category (filter name) |
|---|---|
| `entrepreneurship.ts` | Entrepreneurship & Innovation (incl. career exploration) |
| `leadership.ts` | Leadership & Student Governance (incl. service) |
| `academic.ts` | Academic & Intellectual |
| `global.ts` | Global Affairs & Cultural Exchange |
| `communication.ts` | Communication & Media |
| `writing.ts` | Literature & Writing |
| `arts.ts` | Arts & Performing Arts |
| `sports.ts` | Equestrian & Sports |
| `school.ts` | School & Community |

(`events/index.ts` combines them — you don't need to touch it.)

### Add an event
Open the file for its category and add a record (newest first):

```ts
{
  id: "robotics-workshop-2026",   // lowercase-with-dashes → /work/robotics-workshop-2026/
  title: "Robotics Workshop",
  seoTitle: "Robotics Workshop",           // optional shorter title for the browser tab / Google (use when the title is long)
  organization: "Some Organisation",        // optional
  year: 2026,                               // leave out if you genuinely don't know it
  dateLabel: "March 2026",                  // optional; shown instead of the year
  category: "academic",                     // must match the file (see table above)
  type: "workshop",   // competition | workshop | programme | role | performance |
                      // conference | event | assessment | award | service
  importance: "archive",                    // featured | significant | archive
  summary: "One sharp line.",
  description: "What it was — what the event actually involved.",
  role: "Participant",
  actions: ["Only things you actually did."],
  learning: "What it taught you.",
  whyItMattered: "Why it mattered to you.",
  outcome: "Certificate of completion.",     // non-award outcome
  relatedSkills: ["systems-thinking"],
  relatedEvents: ["junior-make-a-thon"],
  relatedStory: ["building-with-ai"],
  detailsToAdd: "A private note to yourself — never shown or published.",
},
```

It automatically appears in Work → Did (in its year, or under "Along the
way" if it has no year), the Archive, Explore, the filters and any skill
it names. Photos: §8.

**Importance** controls visual weight: `featured` = the big, image-led
treatment (keep this for your strongest stories — about 6–9 across the
site), `significant` = a normal entry, `archive` = compact.

### Add a recognition / achievement
Add a `recognition` to the event it came from:

```ts
recognition: {
  result: "1st Runner-Up",       // the big text in Work → Recognized
  detail: "Out of all finalists", // optional one-liner under it
  category: "entrepreneurship",  // entrepreneurship | academic | arts | sports | other
  level: "major",                // major = large treatment; minor = compact
},
```

An award that isn't really an "event" (like Best Boarder Award) is an
event with `type: "award"` plus a `recognition` — it shows in Recognized,
not in Did.

### Edit / remove an event
Same as projects (§6): edit in place; to remove, delete the record, run
`npm run build`, fix anything it reports, and delete
`public/media/events/<id>/`.

## 8. Photos, galleries and videos

Each record has its own media folder, named exactly like its `id`:

```
public/media/events/<event-id>/     1.png  2.png  3.png  1.mp4 …
public/media/projects/<project-id>/ 1.png  2.png …
```

### Add a photo
Drop it into the record's folder, named with the next number (`4.png`),
and rebuild. That's it: the build scans the folders (`scripts/media-manifest.mjs`),
reads each image's size, **strips hidden metadata** (camera, GPS,
editor/account ids) and adds it to the gallery in number order. JPG, PNG,
WebP, GIF and AVIF all work. Keep images around 1600 px on the long side.

The build also writes smaller copies of every photo into a `_w/` folder
next to it (`scripts/lib/media-variants.mjs` + `scripts/media-thumbs.ps1`;
this uses Windows' built-in image tools — on other machines the originals
are simply used). Cards and thumbnails load those small copies; the photo
viewer loads the original. Never edit or delete `_w/` by hand: copies are
rewritten when you replace a photo and removed when you delete one.
Photos narrower than about 800 px look soft when shown large —
`npm run media -- --small` lists them.

### Add an event image folder
Create `public/media/events/<event-id>/` — the folder name must be the
event's `id` exactly — and put the photos in it. Photos from one event
never go in another event's folder; the folder is what decides where a
photo appears.

### Remove a photo
Delete the file and rebuild. (Hiding it only from the gallery — see
`hide` below — still publishes the file. To keep a photo private, move it
out of `public/`, e.g. to `private-media/withheld/`.)

### Order, captions, alt text, cover, layout
Optional `media` block on the record:

```ts
media: {
  images: [                       // photos listed here come first, in this order;
    { file: "3.png", alt: "…", caption: "…", focus: "50% 30%" },  // unlisted ones follow
    { file: "1.png" },
  ],
  cover: "3.png",                 // the card / preview image (default: first photo)
  hide: ["2.png"],                // leave a file out of the gallery
  layout: "split",                // auto | hero | split | mosaic | filmstrip | stack | stage
  videoCaption: "…",              // caption for every video in the folder
  videos: [{ file: "1.mp4", caption: "…", poster: "2.png" }],
},
```

`focus` sets which part of a photo stays visible when it's cropped
("50% 30%" = centre, upper third). Without a `focus`, a picture whose
shape is far from its frame — a certificate, a wide email screenshot — is
shown whole on a mat instead of being cropped; adding a `focus` tells the
site the crop is intended. With `layout` left out the site picks
one: a single photo → large hero; 2–3 → split; 4–5 → mosaic; 6+ →
filmstrip; photos plus videos → media stage.

### Add a gallery
A gallery is just several photos in the folder — it appears automatically
on the record's page, with a full-screen lightbox (arrow keys, swipe,
Esc). For a gallery somewhere else (a page section), use a `gallery`
block (§13).

### Add a video
Put an `.mp4` (H.264) in the record's folder; it appears in its own video
area with custom controls. Always give it a caption that says what it is.
Videos only start loading as they are about to scroll into view (or when
Play is pressed); a `poster` image, if set, shows until then.
The Inter-House Horse Riding videos are captioned as practice footage —
keep that caption.

## 10. Skills and their evidence

File: **`src/content/skills.ts`**, array `skills`. No percentages — a
skill is proven by the records linked to it.

- **Add/edit a skill:** `{ id, name, category, blurb }` — category is
  `technical | creative | leadership | communication | analytical`.
- **Connect a skill to evidence**, either way (both work, use whichever is
  natural):
  - on the skill: `relatedProjects: ["wizmo"]`, `relatedEvents: [...]`, `relatedStory: [...]`
  - on the project/event: `relatedSkills: ["public-communication"]`

  Events with a recognition show up as recognitions in the skill's proof.

Skill ids: `leadership`, `product-thinking`, `frontend-development`,
`writing`, `design`, `public-communication`, `systems-thinking`. Each
skill has its own link: `/me/#skill-<id>`.

## 12. Beyond: Now, Next, Lab

- **Now** — `src/content/now.ts`. Each item: `{ id, label, value, note?, updatedAt, relatedProjects?, relatedEvents? }`.
  `label` is `building | learning | reading | exploring | goal | challenge`.
  **Update `updatedAt`** (format `"2026-09-27"`) whenever you change an
  item — the page shows the latest date as "Updated September 2026".
- **Next** — `src/content/next.ts`. `{ id, horizon, title, description }`,
  `horizon` is `now | next | later | someday`.
- **Lab** — `src/content/lab.ts`. `{ id, title, status, summary, year, href? }`,
  `status` is `idea | exploring | building | testing | paused | done`;
  `href` optionally links to a related page (e.g. `"/work/wizmo/"`).

## 13. Sections built from blocks (no code)

You can add whole sections without touching components, by listing
**blocks**:

- On a **page** — `src/content/pages.ts` → `pages.<page>.sections`
  (appears near the end of that page).
- On a **project/event page** — the record's `body` field (appears after
  the main write-up).

```ts
sections: [
  { type: "heading", kicker: "Also", text: "Something new" },
  { type: "text", text: "A paragraph.", lead: true },
  { type: "quote", text: "A line.", cite: "Someone" },
  { type: "image", src: "/media/events/innoventure/2.png", alt: "…", caption: "…" },
  { type: "gallery", images: [{ src: "/media/…/1.png", alt: "…" }] },
  { type: "video", src: "/media/…/1.mp4", caption: "…" },
  { type: "cards", cards: [{ title: "…", text: "…", href: "/work/wizmo/" }] },
  { type: "timeline", items: [{ label: "2024", title: "…", text: "…" }] },
  { type: "stat", stats: [{ value: "60+", label: "events" }] },
  { type: "callout", title: "…", text: "…", tone: "accent" },   // accent | warm | quiet
  { type: "link", label: "Read more", href: "/story/", description: "…" },
  { type: "embed", url: "https://…", title: "…", aspect: "16/9" },
],
```

**Remove a section:** delete its blocks (or the whole `sections` array).
The built-in sections of each page (e.g. Me → Skills) are part of the
page design; removing one of those is a code change in
`src/pages/<Page>.tsx`. A genuinely new kind of interaction (not one of
the 12 block types) also needs code.

## 14. Relationships between records

Records connect through ids — never titles, never positions in a list:

| Field | Holds ids from |
|---|---|
| `relatedSkills` | `skills.ts` |
| `relatedProjects` | `projects.ts` |

Links are shown in both directions automatically (if an event names a
skill, the skill shows the event as proof). If you remove a record, the
build lists every reference that still points at it.

## 15. The Easter egg

Clicking the name in the top-left corner three times quickly opens a
password dialog that plays a private video.

- **Text** (title, subtitle, hint, wrong-password message, the link under
  the video): `src/content/site.ts` → `easterEgg`. The footer joke is
  `site.easterEggHint`.
- **Change the video:** replace `private-media/easter-egg/easter-egg.mp4`
  (keep that name), then run
  `node scripts/encrypt-easter-egg.mjs --password <password>` and `npm run build`.
- **Change the password:** run
  `node scripts/encrypt-easter-egg.mjs --password <new password>`, update
  the hint (`easterEgg.hint`) and `npm run build`. The password is not
  stored anywhere in the project — only the encrypted video
  (`public/media/easter-egg/egg.bin`) and a password check (`egg.json`) are
  published. Keep a note of it somewhere private.
- `private-media/` is excluded from git, so the real video exists only on
  this computer (and its OneDrive backup). Don't delete it.

See §23 for what this protection can and can't do.

## 17. Colours and theme

File: **`src/styles/theme.css`** — the only place colours are defined.

- `:root { … }` — dark mode (what every visitor sees first).
- `:root[data-theme="light"] { … }` — light mode.

Main tokens: `--color-ink` (background), `--color-ink-raised` /
`--color-ink-raised-2` (surfaces), `--color-paper` / `-dim` / `-faint`
(text), `--color-azure` (main accent), `--color-lavender` (second accent),
`--color-ember` (warm accent — use rarely). `--atmo-*` tune the background
atmospheres. Dark is always the default; a visitor's choice of light is
remembered on their device.

`--color-paper-dim-raised` / `--color-paper-faint-raised` are mixed from
the text colours above (nothing to set): in light mode they deepen small
labels that sit on cards and panels a touch, because `--color-paper-dim`
has only 4.4:1 on `--color-ink-raised`.

Light mode keeps its full atmospheres (the Home hero's bloom, the Story
wash and chapter cards, each route's lights). Grey text that sits on one
of those tints is deepened locally instead: the tinted area redefines
`--color-paper-dim` / `-faint` as the page grey plus a few percent of
`--color-paper` — see the "Text on the tint" blocks in
`styles/atmosphere.css` (one per route) and in the area files. Your values
in `theme.css` stay exactly as you set them everywhere else. If you change
a text, surface or atmosphere colour, keep small grey text at 4.5:1 or
more against the page, the cards and the tinted areas — raise or lower
that region's percentage rather than fading the tint.

## 18. Animation settings

File: **`src/animations/tokens.ts`** → `motionSettings` (and `EASE`,
`DUR`, `SPRING` above it). Useful switches:

- `revealsEnabled: false` — every section shows immediately, no scroll reveals.
- `depthEnabled: false` — turns off parallax, tilt and pointer depth.
- `revealDistance`, `revealDuration`, `staggerGap` — how far/fast things arrive.
- `tiltMax`, `parallaxStrength` — how strong the 3D effects are.

CSS animations use the matching `--motion-*` values at the top of
`src/styles/motion.css` — change both together. Visitors with "reduce
motion" turned on in their system always get a calm version.

## 19. Adding a new page / URL

URLs always end with a slash (`/story/`, `/work/wizmo/`). Interface state
lives after `#`:

| Link | Opens |
|---|---|
| `/work/#built`, `/work/#did`, `/work/#recognized`, `/work/#all` | a Work lens |
| `/work/#did/leadership` | a lens with a filter (filter = category id from `taxonomy.ts`) |
| `/work/<id>/` | a project or event |
| `/story/#<moment-id>` | a Story moment |
| `/me/#care-about`, `/me/#personal-details`, `/me/#skills`, `/me/#skill-<id>` | Me sections |
| `/beyond/#now`, `/beyond/#next`, `/beyond/#lab` | a Beyond mode |
| `/explore/#built` (`grown`, `tried`, `care`, `proud`) | an Explore lens |

Project and event pages are created automatically for every record. A
genuinely new top-level page needs code (keep the five-destination menu
in mind):

1. `src/pages/NewPage.tsx` — the page component.
2. `src/routes.tsx` — add `<Route path="/new-page" element={<NewPage />} />`.
3. `src/routing/paths.ts` — add a helper to `paths` (e.g. `newPage: () => "/new-page/"`).
4. `src/content/pages.ts` — add its `title`, `description`, heading copy
   (and the key to `PageKey` in `src/types/content.ts`).
5. `src/routing/seo.ts` — add it to `STATIC_PAGES` (this prerenders it
   and adds it to the sitemap).
6. Optional: a menu entry in `site.ts` → `navigation.secondary`.

## 20. SEO

Everything is automatic; this is how it works so you don't fight it.

- **Canonical URLs:** every page declares `https://tanushhlath.com/<path>/`
  (https, no www, trailing slash) as its canonical and `og:url`. Internal
  links always use that exact form.
- **Titles & descriptions:** pages → `src/content/pages.ts`; project/event
  pages → the record's `title` and `summary`. The build bakes them into
  each page's HTML.
- **Link previews:** `og-image.png` by default; project/event pages use
  their cover photo when it's large enough.
- **Structured data:** the homepage describes you (name, school, location,
  LinkedIn); every page has breadcrumbs.
- **`sitemap.xml`** is generated on every build with only real, canonical
  pages — no `#` states, no `?query` URLs, no redirects.
- **`robots.txt`** allows everything and points to the sitemap.
- **Old URLs:** add `aliases: ["old-id"]` to a record and the build
  generates a redirect page at `/work/old-id/` (currently
  `/work/equestrian/` → Inter-School Horse Riding and
  `/work/innovation-competitions/` → InnoVenture). Old `?tab=` links
  (`/work/?tab=did`) still open the right lens and switch to `#did`.
- **http / www / missing slash** are handled by the host, not the code.
  On GitHub Pages: Settings → Pages → tick **Enforce HTTPS**, and point
  `www` at GitHub Pages in your DNS so it redirects to the bare domain.
  GitHub Pages adds the trailing slash itself. (GitHub can't do
  "http + no slash" in a single redirect — Google handles the two steps
  fine. If you ever want exactly one hop, put the site behind Cloudflare
  or move it to Netlify/Cloudflare Pages.)
- Seeing "Page with redirect" or "Alternate page with proper canonical
  tag" in Google Search Console for http://, www or no-slash addresses is
  **expected** — it means Google found the variant and is using the
  canonical page.

## 21. Build, preview and deploy

```bash
npm run dev      # develop: http://localhost:3000, updates as you save
npm run build    # production build → dist/, then copied to the project root
npm run start    # preview the production build: http://localhost:3000
npm run check    # typecheck + lint + link/SEO audits on the last build
npm run media    # rescan media folders only (also runs before dev/build)
npm run icons    # regenerate favicons/social image from the headshot
```

`npm run build`:
1. scans media and strips photo metadata,
2. builds the site,
3. validates every content record (fails with a readable list if an id,
   link or photo is wrong),
4. prerenders every page to real HTML (works when opened directly from
   disk too — double-click `index.html`),
5. audits every internal link and every page's SEO tags,
6. copies the result to the project root (what GitHub Pages serves).

**Deploy:** after a successful build, commit everything and push to
`master`. GitHub Pages publishes the project root within a minute or two.

## 23. Media privacy and protection

What the site does:

- Photos can't be dragged, right-click → "Save image" is blocked on them,
  they can't be selected or copied, and there are no download buttons.
- Videos have custom controls with no download, playback-speed,
  picture-in-picture or casting options.
- Hidden metadata (EXIF, GPS, editor ids) is stripped from every
  published photo on each build.
- The Easter egg video is published **only encrypted**; it can't be
  played or downloaded without the password, and nothing loads until the
  password is right. It blacks out and pauses when the tab or window
  loses focus.
- Photos that showed other people's email addresses, phone numbers or
  other students' full names (email "To:" lines, a team list) were moved
  to `private-media/withheld/` and are not published:
  `innoventure/1.png`, `junior-make-a-thon/1.png` and `3.png`,
  `design-thinking-toi-samsung/2.png`, `pathways-got-talent/2.png`,
  `indiana-university-finance-workshop/1.png`, `harmony-equestrian/1.png`,
  `shistech-theatre/1.png`, `public-speaking/2.png`. Crop out the
  personal details and move one back into `public/media/events/<id>/`
  if you want it shown.
- `detailsToAdd` notes are removed from the site's code when it's built,
  so they're never published — they only exist in your source files.

What it **can't** do — honestly: anything a browser displays can be
screenshotted, screen-recorded or pulled from the browser's developer
tools by someone determined. These measures stop casual saving and keep
private files unplayable without the password; they are not DRM. The
Easter egg's two-digit password could be guessed by someone who tries
all possibilities — it's a fun secret, not a vault. Don't publish
anything you'd be upset to see copied.

## 24. Troubleshooting

- **`npm run build` says "content problems"** — it lists each one with the
  file and field (usually a misspelt id in a `related…` list, or a photo
  named in `media` that isn't in the folder). Fix and rebuild.
- **"Broken link" from the link audit** — a link (`href`) points to a page
  or `#section` that doesn't exist. Use the forms in §19.
- **A new photo doesn't show** — check the folder name matches the
  record's `id` exactly, and that it isn't listed in `media.hide`.
- **The site looks unstyled on `npm run dev`** — stop it (Ctrl+C) and run
  it again; the first start after an install can take a moment.
- **Something looks wrong only on the live site** — run `npm run build`
  then `npm run start` to see exactly what will be published.
