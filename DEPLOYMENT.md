# Deployment Guide

## What gets deployed

`npm run build` produces a `dist/` folder of plain static files — real HTML
for every page (pre-rendered at build time, JS/CSS inlined so each page is
fully self-contained), plus images and favicons. There is no server
process, no Node.js runtime, and no framework-specific hosting requirement.
Any static host works: upload `dist/` and you're done.

The same output is also mirrored onto the project root itself (root
`index.html` plus `story/`, `work/`, `me/`, etc.) so the primary project
folder always has a working copy you can double-click open locally with no
build/server step — but for hosting, upload `dist/` (or the mirrored root
files) either way works since they're identical.

This means you can use **any** of the following — pick whichever is
easiest for you, there's no "recommended" one anymore:

- **Netlify** — drag-and-drop the `dist/` folder at [app.netlify.com/drop](https://app.netlify.com/drop), or connect the GitHub repo and set build command `npm run build`, publish directory `dist`.
- **Cloudflare Pages** — connect the repo, build command `npm run build`, output directory `dist`.
- **GitHub Pages** — build locally (or via a GitHub Action) and push the contents of `dist/` to the `gh-pages` branch.
- **Vercel** — works fine too as a plain static deployment (build command `npm run build`, output directory `dist`) even though the project no longer uses Next.js.
- **Any shared/traditional hosting** (cPanel, etc.) — build locally and upload the contents of `dist/` into your site's public folder (e.g. `public_html/`) via FTP/SFTP.

## Building locally

```bash
npm run build   # type-checks, builds, and pre-renders every route into dist/
npm run start   # serve dist/ locally at localhost:3000, exactly as a real host would
```

Run `npm run build` before pushing anything you're unsure about — a broken
import or type error fails the build loudly instead of reaching production.

## Connecting a custom domain

This is entirely host-specific now (there's no framework dashboard to go
through): whichever static host you pick, follow its own "add a custom
domain" flow — point your registrar's DNS at the host (usually a CNAME or
a set of nameservers), and the host provisions HTTPS automatically.

Once your real domain is live, update the site URL in these two places:

- `dev.html` — the `og:url`, `og:image`, `twitter:image`, and canonical
  values reference `https://tanushhlath.com`. (This is the real source
  file; root `index.html` is generated from it by `npm run build` — don't
  edit `index.html` directly, it gets overwritten.)
- `scripts/prerender.mjs` — the `SITE_URL` constant, used for every page's
  canonical link, Open Graph URL, and `sitemap.xml`.

## Every future update

However your host is connected to the repo, pushing to your main branch
(or re-running the build and re-uploading `dist/`) is the entire deploy
step — there's no build cache or serverless-function concept to worry
about since everything is static files.

## Analytics

No analytics are wired up yet, by design — add them when you're ready to
publish for real rather than carrying tracking through development.
Any static-friendly option works (Plausible, Fathom, or your host's
built-in analytics if it has one). Avoid anything that needs a
cookie-consent banner unless you're prepared to build one — it works
against the site's tone.

## SEO checklist (already done, verify before going public)

- [x] Per-page `<title>` / meta description (`src/pageMeta.ts` + each
      page's `<Meta/>`, baked into the static HTML by `scripts/prerender.mjs`)
- [x] Open Graph + Twitter card metadata (`index.html`, overridden per
      page by the prerender step)
- [x] `sitemap.xml` and `robots.txt` (generated by `scripts/prerender.mjs`,
      auto-includes every project and experience)
- [x] Semantic HTML (`<header>`, `<main>`, `<article>`, `<nav>`, heading
      hierarchy)
- [ ] Replace `public/og-image.svg` with a real 1200×630 JPG/PNG
- [ ] Replace placeholder content in `src/content/` with real information —
      search-engine value comes from real text, not structure
- [ ] Update the site URL in `index.html` and `scripts/prerender.mjs` once
      the domain is live
